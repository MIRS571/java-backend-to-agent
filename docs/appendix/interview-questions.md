# 面试复习问题

这些问题检查的不是 API 背诵，而是你能否解释执行流程、工程取舍和系统边界。建议先口述，再用图或伪代码补充；正文不直接提供标准答案。

## LangChain 与工具调用

1. `invoke`、`ainvoke`、`stream` 和 `astream` 分别适合什么场景？
2. Tool Calling 与直接让模型输出一段自然语言指令有什么本质差异？
3. Structured Output 能保证哪些事情，不能保证哪些事情？
4. 模型返回 `tool_calls` 后，为什么仍需要应用代码执行工具并回传结果？

## RAG

5. RAG 的入库流程和查询流程为什么必须分开？
6. Embedding 模型、向量数据库和 Retriever 分别承担什么职责？
7. 为什么多租户过滤必须进入 Qdrant 或数据库查询条件？
8. 检索命中率正常但最终答案错误时，你会按什么顺序排查？

## LangGraph

9. State、Runtime Context 和 Checkpointer 各自保存什么？
10. 普通 Edge、条件路由和 ToolNode 分别解决什么问题？
11. `interrupt` 恢复时为什么必须复用相同的 `thread_id`？
12. 什么场景需要 LangGraph，什么场景使用一条 LCEL Chain 已经足够？

## 企业工程

13. SSE 为什么通常使用 WebClient/Flux 转发，而不优先使用 OpenFeign？
14. Redis 适合保存哪些 Agent 数据，又不应该成为哪些数据的事实来源？
15. Java 与 Python 在企业 Agent 系统中应如何划分职责？
16. 如何实现请求幂等、超时、重试和租户隔离，同时避免重复执行有副作用的工具？
17. 如何证明一个 Agent 项目不仅“能回答”，而且可评估、可追踪、可控？

## 自测标准

| 水平 | 判断标准 |
| --- | --- |
| 未掌握 | 只能说出名词或复述定义，无法描述输入、输出和执行顺序 |
| 基本掌握 | 能解释最小 Demo，并说出至少一个局限 |
| 工程掌握 | 能比较替代方案，说明失败路径、状态归属和安全边界 |
| 面试可用 | 能结合自己的项目，用架构图、指标和具体故障案例完成说明 |
